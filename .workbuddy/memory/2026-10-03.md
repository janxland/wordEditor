# 2026-10-03

## 产品化审视 + P0 落地（面向「卖给校园团队」）

背景：用户要把wordEditor 卖给校园团队，让对方用 WorkBuddy / ZCode 等 MCP 客户端
接入，自己搭学校论文模板、自己组流水线。要求解耦合、单个入口、可嵌工作流、防技术盗窃。

### 生态位核查（联网）

- PaperRed / 大以 / 毕业之家：在线一键排版 SaaS，2000+ 模板库当护城河，**不给改模板的权**。
- mcp-pandoc（PyPI 0.11.0，官方 MCP 项目收录）：只有 `convert-contents` 格式转换，
  **零学校版式知识**，reference.docx 得用户自己找。→ 这才是真正的竞品，不是 PaperRed。
- 独占格：市面工具都假设「排版规则已知且固定」；`template_factory` 能把任意学校官方 docx
  反向复刻成可用模板，这是「没有模板的学校也能自助接入」的唯一路径。

### 发现并修掉的三个硬伤

1. **MCP 工具面与 docstring 承诺不符**：实测 `tools/list` 只返回 7 个，
   缺的恰是最变现的 `analyze_docx` / `clone_template`（`clone_core` 15 个函数都实现了，
   没接进 MCP）。已补 → 实测 9 个。
2. **Electron 没打包 Python**：`electron-builder.yml` 的 extraResources 只有
   api-node / web / config / contracts / pandoc，模板工厂（100% 在 Python）不在产品里。
   → 桌面版能导出但不能「上传学校模板」。**未修，见下方待办。**
3. **仓库 public + 无 LICENSE**：等于把要卖的东西全部公开（10 模板 + 工厂源码 + DSL）。
   已补专有 LICENSE + `docs/ip-protection-checklist.md`，但**转私有需用户自己在 GitHub 操作**。

### 删掉的冗余（都有硬证据）

1. **`services/api-python/run.py`（67 行）—— 第二套 CLI，与 `bin/we` 重叠**。
   它的 4 个能力（build / preview-styles / extract-docx / ref-styles）已被
   `bin/we` + HTTP `/api` 全覆盖，README 还在推它。删掉，能力并入 `bin/we`：
   新增 `we extract`（docx→md 反向闭环）、`we ref-styles`。
2. **3 个零引用死代码**（`git grep` 全仓确认零外部引用）：
   - `clone_core.build_with_cover`（16 行）→ 能力已由 `clone_template` +
     `build_to_workspace` 组合覆盖，且是工厂路径的旧实现
   - `ooxml_numbering.inject_heading_numbering` + 5 个内部函数 → 编号注入实际走
     `ooxml_multilevel.apply_multilevel`。**该文件 97 行 → 15 行，只剩
     `HUTB_HEADING_NUM_ID = 2`（被 ooxml_util / postprocess_document import）**
   - `preview_images.default_preview_image_urls`（8 行）→ 预览只用 `materialize_markdown_images`

### 业务能力补齐（不是冗余，是缺口）

`pipeline/build.py` 有 20 个参数，但 `direct.build_to_workspace` 只用了 4 个 ——
**密码、页眉页脚、文档元数据全部没暴露**，CLI/MCP 根本用不上。
已加 `extra_args` 透传（不逐个映射，避免两处参数表），`we build` 暴露：
`--password-env/--password/--author/--remark/--doc-title/--header-text/--footer-text/
--header-align/--footer-align/--no-postprocess/--no-html-pipe`。
实跑验证：creator/description/title 真写进 docProps，header 部件含页眉文字，
settings.xml 有 writeProtection。

### 修掉的质量缺陷（本轮自查 + 实证）

1. **`yaml.safe_dump` 往返洗掉 spec.yaml 全部注释**（22 → 0）。spec 顶部有铁律注释，
   那是资产。改**文本级定点替换**，注释 22 → 22 全保住。
   不引 ruamel（不新增依赖）。
2. **定点替换写坏 YAML 结构**：`(\S.*)$` 会跨到下一行把缩进吃掉，产出结构损坏的 spec
   （实证抛 ParserError）。`set_scalar` 限制单行 + 必须传 `indent`（`title` 在缩进 0
   的多行映射与缩进 2 的单行标量各出现一次）+ 每次替换后 `yaml.safe_load` 守卫。
3. **守卫层级写错**：`set_scalar` 内按 `key` 顶层查，实际要查 `tail.rubric.k`
   → 永远返回 False，4 项静默不填。必须传 `parent` 走完整层级。
4. **stdout 被进度信息污染** → `we clone` 的 JSON 无法被 `jq`/`json.load` 消费，CI 不可用。
   `direct.py` 4 行 print + `tpl_factory/assets.py` 1 行改走 stderr。现在 stdout 纯 JSON。
5. **错误消息占位符没替换**：`templates/@TID@ 已存在` → 应为 `templates/<id> 已存在`。
6. **过度设计回退**：`other_rows` 我写进了 autofill，但 spec 模板与人工填写的样板里
   都没这个键（不是必需字段）→ 删掉那段。

### 关键教训

- **AST 才是死代码的可靠判据**：shell `grep -r` 的 `` 不生效、tpl_factory 包内互调
  会误报；`grep` 全仓还会超时。用 `ast` 解析 + `git grep` 双证。
- **做 A/B 对照别 `cp` 回源文件**：中途一次 `cp` 把收敛版覆盖回97 行旧版，
  又`wc -l` 才察觉。正确做法：旧版放独立目录 + `try/finally` 还原 + 跑完断言行数。
- **删代码的证据标准**：不是「看着没引用」，而是 **28/28 docx 部件 strip 时间戳后
  逐字节一致**（唯一差异是 `docProps/core.xml` 的 dcterms 时间戳）。
