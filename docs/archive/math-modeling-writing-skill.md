# 数学建模论文写作约束 Skill（喂给外部 AI 用）

> 用途：你（外部模型）将为湖南工商大学 **数学建模** 模板（`hutb-math-modeling`）撰写 Markdown 论文，文件随后由 `scripts/build.py` 经 Pandoc + 后处理导出为 DOCX。**输出格式必须严格满足下列约束**，否则后处理脚本会失败或排版错乱。

---

## 0. 输出要求（最重要）

1. **只输出一个 Markdown 代码块**（或纯 Markdown 文本），不要寒暄、不要解释、不要附录"我做了什么"。
2. 使用 **UTF-8、LF 换行、半角标点的代码/公式**；正文标点用中文全角。
3. 文件结构固定为：YAML front-matter → 一级标题（论文题目）→ 摘要段 → 关键词行 → 正文章节。
4. 全文 **不写 Word 域代码、不写 HTML、不写 `<div>` / `<span>` / `style=`**。

## 2. 标题规则（关键，错了导出就乱）

| 你写 | 渲染后含义 | 后处理识别为 |
|------|-----------|--------------|
| `# 引言` | 章 | 标题 1（自动加 "一、""二、"） |
| `## 问题分析` | 节 | 标题 2（自动加 "1.1""2.1"） |
| `### 子节` | 小节 | 标题 3（自动加 "1.1.1"） |
| `#### …` | 更细 | 标题 4 |

**绝对不要**自己手写 "一、""1.1""1.1.1" 等编号前缀——`hutb-math-modeling` 模板由 Word 多级列表（numId=2）自动编号，你手写会变成"一、一、引言"。

**允许的手写前缀**（后处理会剥掉，但建议直接用 `#` ~ `####`）：

- `一、绪论` → 标题 1
- `1.1 研究背景` → 标题 2

> 优先用 `#` 系列；只有在批量改写历史稿件时才用前缀写法。

## 3. 公式

### 行内公式

- 推荐：`$E=mc^2$`
- 也可：`\(E=mc^2\)`

### 独立公式

```markdown
$$
N_t = \gamma_1 \gamma_2 \gamma_3 N_{\max}
$$
```

**禁止事项**：

- 公式里 **不要混入中文**（中文写在公式外）。
- 不要使用未补反斜杠的命令（如 `fracab` ❌，必须 `\frac{a}{b}` ✅）。
- 不要在 `$…$` 内嵌行号 `#`、注释 `%`。
- 多行公式用 `aligned`：

  ```markdown
  $$
  \begin{aligned}
    \Delta S(t) &= S_0 + \sum_{i=1}^3 S_U(i,t) - \sum_{i=1}^3 S_D(i,t) \\
    k(t)        &= \frac{\Delta S(t)}{3L}
  \end{aligned}
  $$
  ```

- 矩阵用 `bmatrix`；分段函数用 `cases`。
- 希腊字母必须命令写法：`\alpha \beta \gamma \omega_f`，不要直接打 `α β γ`。

## 4. 图片

```markdown
![图 1 事故横断面示意图](images/fig01.png)
```

约束：

- 路径统一相对 `images/`，文件名小写 ASCII（`fig01.png`、`flowchart.png`）。
- alt 文本写"图 N 题注"——后处理会转成 Word 题注样式。
- **每张图必须在正文中显式引用**："如图 1 所示…"。
- 不要并排图（不要用 HTML/表格塞两张图）；竖排即可。
- 不要写图片宽度属性。

---

## 5. 表格

```markdown
| 参数 | 取值 | 单位 |
| --- | --- | --- |
| 上游车流量 | 1500 | pcu/h |
| 路段长度 | 140 | m |
```

约束：

- 必须是 GFM 管道表格，**首行表头 + 第二行分隔线**。
- 表前一行写："表 1 模型参数取值"（独占一段、无 `#`）。
- 单元格内**禁止**换行 `<br>`、HTML、嵌套表格。
- 数值右对齐时用 `| ---: |`；默认左对齐即可。

---

## 6. 列表

- **无序**用 `- `；**有序**用 `1. 2. 3.`（不要 `1) `、不要 `①`）。
- 列表项之间不留空行（除非项内含代码块/公式块）。
- 不要在列表里直接放 `#` 标题。

---

## 7. 代码块

````markdown
```python
import numpy as np
def solve(...):
    ...
```
````

- 三反引号 + 语言标签（`python` / `matlab` / `c` / `text`）。
- 附录里集中放完整代码；正文穿插的算法片段不超过 30 行。
- **不要**用缩进式代码块。

---

## 8. 参考文献与正文引用

正文引用直接写方括号 + 数字：

```markdown
…基于二流理论 [1]，结合 BP 神经网络 [2,3]…
```

参考文献节（位于 `# 参考文献` 之下，**每条独占一段、不能写成列表**）：

```markdown
<a id="Ref1"></a>[1] 张三, 李四. 城市道路通行能力研究 [J]. 交通工程学报, 2018, 18(4): 22-30.
<a id="Ref2"></a>[2] Smith J. Traffic flow theory [M]. New York: Springer, 2020.
```

要求：

- 每条前缀 `<a id="RefN"></a>` 必须存在（后处理用它生成超链接书签）。
- 文献类型标识：`[J]` 期刊、`[M]` 专著、`[D]` 学位论文、`[C]` 会议、`[R]` 报告、`[EB/OL]` 电子。
- 编号与正文 `[N]` 严格一一对应、连续递增。

---

## 9. 数学建模论文专属内容要求

写作时**必须覆盖**以下要点，否则视为不合规：

1. **摘要**：交代背景 → 每个问题的模型/方法 → 主要结论数值。300–500 字，禁止"本文研究了…具有重要意义"等套话占段。
2. **模型假设**：5–10 条，每条一句、可证伪、给出工程理由。
3. **符号说明表**：所有出现 ≥2 次的符号必须列出，含单位。
4. **每个问题**按 `问题分析 → 模型建立 → 模型求解 → 结果分析` 四节展开，缺一不可。
5. **模型求解**必须给出：
   - 算法/求解步骤（编号列表）
   - 关键参数取值（表格）
   - 求解结果（数值 + 图）
   - 灵敏度 / 误差 / 检验（若适用）
6. **模型评价**：优点 ≥3 条、缺点 ≥2 条、推广方向 ≥1 条。
7. **参考文献** ≥10 条，至少 3 条近 5 年期刊文献，至少 1 条英文文献。
8. **附录**：完整可运行代码 + 必要的中间结果表。

---

## 10. 写作风格

- 第三人称、客观陈述。禁止"我""我们""笔者"。
- 段落长度 3–8 句；不要"一段一句"。
- 中英文 / 中文与数字其内**不加空格**（Pandoc 中文排版会处理）；但 **行内公式 `$…$` 与中文其内不要加空格**。
- 中文标点用 `，。：；""''（）` 全角；公式、代码、英文夹注内用半角。
- 不要使用 emoji、不要使用 `**加粗**` 充当标题、不要用 `> 引用` 表达普通文本。
