# 数学建模论文写作规范（外部 AI 撰稿 Skill）

> 用途：你（外部模型）将为湖南工商大学 **数学建模** 模板 `hutb-math-modeling` 撰写 Markdown 论文。文件随后由 `scripts/build.py` 经 Pandoc + 后处理脚本（`postprocess_document.py` / `postprocess_styles.py`）导出为 DOCX。
> **输出必须严格满足本规范**，否则会出现"双标题""章号错乱""公式乱码"等问题。

---

## 0. 输出要求（最重要）

1. **只输出一份 Markdown**，不要寒暄、不要解释、不要列"我做了什么"。
2. UTF-8 / LF 换行。正文中文标点用全角，代码与公式内部用半角。
3. 文件骨架固定：YAML front-matter → 摘要段 → 关键词行 → 正文章节。
4. 全文 **禁用** HTML（`<div>`/`<span>`/`<br>`/`style="..."`）、Word 域代码、emoji。

---

## 1. 论文题目只能写一次（避免"多出一个一级标题"）

> 这是历史样例最容易踩的坑。原因如下：

Pandoc 在 `reference.docx` 模板里，会把 YAML 中的 `title:` 渲染为一个独立的 **Title 段落**（本仓库 `templates/hutb-math-modeling/styles.yaml` 中已定义 `Title` 自定义样式：黑体 18pt 居中加粗）。
如果你同时再写一个 `# <题目>` 作为一级标题，后处理会把它识别成"标题 1"，并自动加上 `一、` 多级编号，从而出现两个题目：

```
车道被占用对城市道路通行能力的影响           ← YAML title 渲染的 Title
一、车道被占用对城市道路通行能力的影响        ← H1 被加上章号
二、问题重述                                  ← 原本应是"一、问题重述"
```

### 正确做法（**只用 YAML title，不要写题目 H1**）

```markdown
---
title: 共享单车调度优化模型研究
---

摘要

<300–500 字摘要……>

关键词：关键词1、关键词2、关键词3、关键词4、关键词5

# 问题重述          ← 这是第一个 H1，后处理后变成 "一、问题重述"

## 问题背景         ← "1.1 问题背景"

...
```

### 兜底做法（确实想保留 H1）

若你的工作流必须有 `# <题目>`，那就 **删除 YAML 的 `title:` 字段**：

```markdown
---
---

# 共享单车调度优化模型研究

摘要
...
```

> **二者只能取其一**。本规范默认推荐**第一种**（保留 YAML `title:`、删除题目 H1），这样 `# 问题重述` 自然成为第一章。

## 3. 标题规则（关键，错了导出就乱）

模板 `hutb-math-modeling` 使用 **numId=2** 多级列表，由 Word 自动编号（参见 [templates/hutb-math-modeling/styles.yaml](templates/hutb-math-modeling/styles.yaml#L48-L80)）：

| 你写的 Markdown | 渲染后 | 自动编号示例 |
|----------------|--------|--------------|
| `# 问题重述`   | 标题 1 | 一、问题重述 |
| `## 问题分析` | 标题 2 | 1.1 问题分析 |
| `### 子节`     | 标题 3 | 1.1.1 子节 |
| `#### 更细`   | 标题 4 | 1.1.1.1 |

**绝对不要**自己手写 `一、`、`1.1`、`1.1.1` 前缀——会被自动编号叠加成 `一、一、引言`。

> 后处理（[scripts/postprocess_document.py](scripts/postprocess_document.py)）也支持识别手写前缀并剥离，但**强烈建议**统一使用 `#`～`####`，不要混用。

## 4. 公式

### 行内公式

- 推荐：`$E=mc^2$`，也可：`\(E=mc^2\)`

### 独立公式

```markdown
$$
N_t = \gamma_1 \gamma_2 \gamma_3 N_{\max}
$$
```

### 禁止事项

- 公式内 **禁混中文**（中文写在 `$…$` 外）。
- 命令必须带反斜杠：`\frac{a}{b}` ✅；`fracab` ❌。
- `$…$` 内禁止行号 `#`、注释 `%`。
- 多行公式用 `aligned`、矩阵用 `bmatrix`、分段函数用 `cases`。
- 希腊字母用命令：`\alpha \beta \gamma \omega_f`，不要直接打 `α β γ`。

---

## 5. 图片

```markdown
![图1 事故横断面示意图](images/fig01.png)
```

- 路径相对 `images/`；文件名小写 ASCII（`fig01.png`、`flowchart.png`）。
- alt 文本写 `图 N 题注` —— 后处理转为 Word 题注。
- **每张图必须正文引用**（"如图1 所示…"）。
- 不要并排图、不要写宽度属性。

---

## 6. 表格

```markdown
| 参数 | 取值 | 单位 |
| --- | --- | --- |
| 上游车流量 | 1500 | pcu/h |
| 路段长度 | 140 | m |
```

- 必须是 GFM 管道表格（首行表头 + 第二行分隔线）。
- 表前一段独立写 `表 N 表题`（无 `#`）。
- 单元格 **禁止** `<br>`、HTML、嵌套表格。
- 数值列右对齐用 `| ---: |`。

---

## 7. 列表

- 无序用 `- `；有序用 `1. 2. 3.`（禁用 `1)`、`①`）。
- 同一列表项之间不留空行（含代码块/公式块除外）。
- 列表内不要直接放 `#` 标题。

---

## 8. 代码块

````markdown
```python
import numpy as np
def solve(...):
    ...
```
````

- 三反引号 + 语言（`python`/`matlab`/`c`/`text`）。
- 正文穿插的算法片段 ≤ 30 行；完整代码放附录。
- 禁用缩进式代码块。

---

## 9. 参考文献与正文引用

正文：`…基于二流理论 [1]，结合 BP 神经网络 [2,3]…`

参考文献节（在 `# 参考文献` 之下，**每条独占一段，不要用列表**）：

```markdown
<a id="Ref1"></a>[1] 张三, 李四. 城市道路通行能力研究[J]. 交通工程学报, 2018, 18(4): 22-30.
<a id="Ref2"></a>[2] Smith J. Traffic flow theory[M]. New York: Springer, 2020.
```

- 每条前缀 `<a id="RefN"></a>` 必须存在（后处理用它生成 REF 书签 + 上标超链接）。
- 文献类型：`[J]` 期刊、`[M]` 专著、`[D]` 学位论文、`[C]` 会议、`[R]` 报告、`[EB/OL]` 电子。
- 编号与正文 `[N]` 一一对应，连续递增。

---

## 10. 数学建模专属内容要求

写作时**必须覆盖**：

1. **摘要** 300–500 字：背景 → 每个问题的模型/方法 → 主要结论数值。禁套话。
2. **模型假设** 5–10 条：每条一句、可证伪、附工程理由。
3. **符号说明表**：所有 ≥2 次出现的符号都列出，含单位。
4. **每个问题** 必含 `问题分析 → 模型建立 → 模型求解 → 结果分析` 四节。
5. **模型求解** 必给出：算法步骤、关键参数表、求解结果（数值+图）、灵敏度/检验（如适用）。
6. **模型评价**：优点 ≥3 条、缺点 ≥2 条、推广 ≥1 条。
7. **参考文献** ≥10 条；近 5 年期刊 ≥3 条；英文 ≥1 条。
8. **附录**：完整可运行代码 + 关键中间结果。

---

## 11. 写作风格

- 第三人称、客观陈述；禁"我""我们""笔者"。
- 段落 3–8 句；忌"一段一句"。
- 中文与公式 `$…$` 之间 **不要**加空格。
- 中文标点全角；代码、英文夹注内半角。
- 不要 emoji，不要用 `**加粗**` 充当标题，不要 `> 引用` 充当普通正文。
