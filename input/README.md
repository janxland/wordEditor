# input/ · 代码样例与回归输入（**要入库**）

> 跟 `jobs/`（接单区，不入库）的分界见末尾表格。这是**代码资产**，别删别改。

## 这里放什么

| 内容 | 说明 |
|---|---|
| 模板样例 md | 每个模板的示范输入，用来验证版式跑通 |
| **回归基线输入** | 产物等价回归（E6）固定用它构建 |
| `images/` | 样例 md 引用的图片（20 个文件） |

## ⚠️ 两条硬约束

1. **`暑假社会调查报告-样例.md` 不能删、不能改。**
   去冗余每轮的 E6（产物 **28/28 部件逐字节一致**）就是用
   `we build input/暑假社会调查报告-样例.md -t hutb-guanke` 构建的。
   改一个字，改前/改后基线就对不上，回归直接失效。
2. **`金融大数据课程论文-样例.md` 同理**，是 `hutb-jinrong-bigdata` 的样例。

## 客户稿件不要放这里

客户来稿属于 `jobs/`，不是这里。放错的代价：工作区永远脏、仓库体积失控
（历史上两单 41M 堆在这里）、客户内容进版本库有隐私与版权风险。

## 分界表

| | `input/`（这里） | `jobs/`（接单区） |
|---|---|---|
| 内容 | 模板样例、回归输入、随库图片 | 客户来稿、在建工作区、交付物 |
| 入库 | ✅ 是 | ❌ 否（整目录 `.gitignore` 忽略） |
| 能删吗 | 不能（回归依赖） | 随时可清 |

**判断口诀**：「删掉会不会让别人跑不通这个项目」—— 会 → 这里；不会 → `jobs/`。
